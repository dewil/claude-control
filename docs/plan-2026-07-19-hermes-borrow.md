## 1. Agent-scoped outbox (агент -> человек)

Санкционированный примитив свободного текста от mission-агента оператору. Сейчас: pull через `status_line` + push инфры (`notify`), свободного текста агента нет.

- **Не строить второй транспорт**: generic `claude-agent-tgbot notify` уже существует (им шлет дайджест лимитов) - outbox делается слоем над ним.
- Атрибуция по месту, не по аргументу: миссия пишет json-файлы в свой `~/.claude-control/agents/<name>/outbox/`, доставляет доверенный процесс (reconciler/tgbot), имя агента берется из пути. Прямой generic notify миссии не выдавать. Оговорка: при same-UID Bash это защита от случайной подмены, не от злонамеренной (настоящая граница - trust tier, см. бэклог/Docker).
- Durable-очередь, отметка доставки, лимиты размера и частоты (троттлинг), префикс `[агент <name>]` в сообщении.
- Вписывать после этапа 9 (использует ту же дисциплину очередей).

Критерий: миссия с `autonomy=act` может отправить оператору произвольное сообщение; оно доходит в TG с атрибуцией и троттлингом; недоставка видна в сводке.

## 2. Nudge на harvest-canon (правило-финализатор, канон)

Сейчас вызов harvest-canon зависит от памятливости сессии. Systematize, но **не Stop-hook'ом**: hook срабатывает на техническое завершение хода (не отличает промежуточный ответ от финала задачи), рискует циклами и шумом.

- Короткое канон-правило (rules/): "в конце нетривиальной завершенной задачи классифицируй результат: канон-кандидат / проектная память / ничего; наружу - одна строка, и только при наличии кандидата".
- Предпосылка выполнена: контракт кандидата в harvest-canon обновлен под canon-fleet.
- Оформлять через сам harvest-canon (правило - канон-кандидат, зарегистрировать по новому контракту).

## 3. transcript-search MVP (FTS5 по транскриптам сессий)

"Что мы решали по X месяц назад" по требованию. Ownership раздельный: **toolkit** - скилл + индексатор-CLI (рядом с session-cost); **control** - тонкий адаптер (scope агента, worktree-slug, takeover).

Спека MVP (по codex):

- индексировать только top-level сессии; `subagents/` - отдельный opt-in scope;
- инкрементально по byte-offset (на источник: inode/device, size, mtime, offset; уменьшение/подмена файла = rebuild источника); незавершенный хвост без newline не индексировать;
- идентичность документа - session ID + message identity, не pathname (takeover физически переносит транскрипт); tombstone для исчезнувших файлов (event-транскрипты чистятся через 14 дней);
- индексировать только user/assistant text, без tool input/output;
- глобальный индекс в `~/.local/share/` (0700, файлы 0600), не в git/cloud-sync/проекте;
- поиск только on-demand, без автовпрыска "похожей памяти" в контекст;
- русский: unicode61 + prefix (морфологии нет), trigram - позже (индекс заметно тяжелее);
- объем уже ~1230 JSONL / ~573 MiB - MVP ограничить ролями/длиной записи/scope, замерить размер и latency до расширения.

CLI: `index` (инкремент), `search <query> [--project] [--since]`, `forget <session>`, `rebuild`.

## Бэклог (осознанно отложено, до измеримого сценария)

- **TG-топики пер-агент** - опциональный режим, если появится >1 оператора или десятки одновременных миссий. Сейчас бот принципиально private-only (`claude-agent-tgbot:88` - "группа правом не является"), топики = смена модели авторизации. Пока - усиленный map (в дизайне этапа 9).
- **Multi-judge приемка** - не вводить (FSM: один review_job; судьи делят слепое пятно). Вместо этого: machine-readable `acceptance.criteria[]` с coverage по каждому критерию + enforce списка критериев в обычном `agent create`, не только в /solo.
- **Docker trust-tier** для недоверенных миссий - требует backend seam (reconciler жестко на systemd-run/tmux/worktree). Важно: если миссия реально враждебна, same-UID Bash - не граница вообще; тогда это предпосылка, а не опция. Дешевая граница уже есть - event-агент без Bash/write/web из пустого cwd.
- **/learn-команда оператора** (в т.ч. кнопка "в канон" при accept) - закрывает слепое пятно harvester'а: он питается только revise/reject, удачная техника принятой с первого раза миссии не всплывает. Рассмотреть вместе с этапом outbox.
- **Journey/timeline миссии** - операторская проекция поверх `events.jsonl` + приемки + комментариев ("цель -> итерации -> вмешательства -> вердикт"), не новое хранилище. После этапа 9.
- **Скаутинг agentskills.io / awesome-hermes-agent** - только источник идей; путь: идея -> переимплементация под свои инварианты -> проверка лицензии -> review -> канон. Без автоимпорта, популярность - не сигнал доверия.
