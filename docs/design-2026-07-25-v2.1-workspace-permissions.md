# V2.1: workspace и пояса прав для event-агентов

Контракт этапа (SDD). Продолжение `design-2026-07-25-v2-runtime-drain.md` (V2.0). Реализация обязана пройти тесты, выведенные отсюда.

## Цель

Task-агент получает руки: прогон идет не в пустом приватном каталоге, а в рабочем пространстве проекта (git-worktree или сама папка), с пер-задачными правами из спеки вместо жесткого blacklist. Существующие агенты не меняются ни в чем.

## 1. Поля спеки

```yaml
project: /abs/path            # уже есть в схеме; обязателен при workspace != none
workspace: worktree           # worktree | direct | none; отсутствие = none
permissions:                  # опционально; отсутствие = старый blacklist
  allow: ["Edit(//<path>/**)", "Bash(git commit:*)", ...]
  deny:  ["WebFetch", ...]
permission_mode: default      # опционально; ТОЛЬКО acceptEdits | default; дефолт default
```

**Валидация пояса - в двух местах, fail-closed (аудит V2.1, blocker 1 / major 2):**

- `create`: `permission_mode` вне {отсутствует, `default`, `acceptEdits`} - exit 2. `bypassPermissions` и любой другой режим CLI запрещены жестко: они снимают весь пояс. `permissions` обязан быть map'ом, `allow`/`deny` - списками строк (иначе exit 2).
- `runner` (defense in depth, спека могла быть отредактирована после create): режим вне белого списка -> принудительно `default`; структура `permissions` не map / не списки строк -> **старый blacklist-argv** (строже) + alert `spec_invalid`. Прогон никогда не идет с непроверенным поясом и никогда не падает исключением из-за формы спеки.

Валидация в `claude-rc-agent create` (в event-ветке, рядом с существующими проверками source/autonomy):

- `workspace` вне {отсутствует, none, worktree, direct} - fail (exit 2, как существующие валидации create).
- `workspace: worktree` -> `project` обязан быть git-репозиторием (`git -C rev-parse`); иначе exit 2.
- `workspace: direct` -> `project` обязан существовать и быть каталогом с правом записи; иначе exit 2.
- **Ослабление autonomy**: сегодня event жестко требует `autonomy: suggest`. Новое правило: event с блоком `permissions` в спеке может иметь `autonomy: act` (правами управляет пояс, не autonomy); event БЕЗ `permissions` - по-прежнему только `suggest`.

## 2. Worktree при create (event + workspace: worktree)

По образцу mission-пути (staging -> атомарная публикация, тот же EXIT-trap/откат):

- Ветка: `task/<name>-<inc8>`, где `inc8` - первые 8 символов `incarnation` из только что сгенерированного control.json (фенсинг против пересозданий). Существующая одноименная ветка - fail-closed (exit 2) с откатом staging. Остатки веток прошлых инкарнаций (`task/<name>-<другой-inc>`) создание НЕ блокируют - их убирает maintenance/completion.
- **Тестовый шов**: env `CLAUDE_AGENT_TEST_INCARNATION` (если задан при create) подменяет генерируемую incarnation - только для детерминированного теста коллизии ветки; в проде не используется.
- Команда: `git -C <project> worktree add -b task/<name>-<inc8> "$tmp/work" HEAD`; публикуется как `$AGENTS_DIR/<name>/work`; после mv - `git worktree repair` (как у mission). **Провал repair не молчит** (аудит V2.1, minor 8): агент уже опубликован (откат невозможен - trap снят), поэтому CLI печатает явное предупреждение в stderr и пишет событие `worktree_repair_failed` в `events.jsonl`; факт виден оператору, ручная починка не теряется.
- Каталог `run/` продолжает создаваться (нужен для `workspace: none` fallback и обратной совместимости).

## 3. Генерация settings и общий argv-хелпер

- **На каждый прогон** (single source = спека): если в спеке есть `permissions`, runner перед спавном durable пишет `agents/<name>/agent-settings.json` = `{"permissions": {"allow": [...], "deny": [...]}}` из спеки и строит argv: `--settings <файл> --setting-sources user --permission-mode <permission_mode>` (образец потребления - mission-путь `claude-agent-session`). Хардкод `--disallowedTools ...` при этом НЕ передается.
- Спека без `permissions` -> старый argv с blacklist байт-в-байт (существующие агенты).
- **Общий хелпер** сборки headless-argv, параметризованный политикой (blacklist-список | settings-файл+mode), используется в `run_event` и `claude-agent-review`. Argv ревьюера обязан остаться байт-в-байт прежним (его расширенный blacklist - его политика).

## 4. cwd прогона и trust

- `workspace: none` -> `agents/<name>/run` (как сейчас).
- `workspace: worktree` -> `agents/<name>/work`.
- `workspace: direct` -> `spec.project`.
- **Trust preseed**: для workspace != none runner перед спавном идемпотентно проставляет `projects[<realpath(cwd)>].hasTrustDialogAccepted = true` в `$CLAUDE_CONFIG_DIR/.claude.json` (обобщить существующий RMW-блок из `claude-agent-session:38-58` в общую функцию/скрипт; headless `-p` не может пройти trust-диалог интерактивно). Ключ - резолвнутый путь.
- **RMW под локом** (аудит V2.1, major 5): `.claude.json` - глобальный файл, его пишут mission-старты, event-прогоны и интерактивный claude. Preseed обязан идти под `flock` на `<config>/.claude.json.lock` с перечитыванием под локом и **уникальным** tmp (`mkstemp` рядом с целью), иначе два старта теряют чужие правки, а общий `.preseed.tmp` рвет файл.
- **Сохранить прежнее поведение на битом JSON** (аудит V2.1, minor 6): нечитаемый `.claude.json` -> писать минимальный валидный документ с trust (как делал inline-код mission до выноса), а не тихо выходить.

## 5. Ретеншн транскриптов

`transcripts_cleanup` сейчас пересобирает slug от захардкоженного `agent_dir/run` - на новых cwd он чистил бы не тот каталог. Контракт:

- Функция принимает фактический **резолвнутый** (`os.path.realpath`) cwd прогона параметром; slug считается от него. Это существенно: `$AGENTS_DIR` может лежать за симлинком (`/home/dwl/... -> /data/...`), а дочерний claude слугует физический путь - от лексического пути слот не совпадет и ретеншн не сработает никогда (аудит V2.1, minor 7; тест U9 должен считать ожидание тоже от realpath).
- Чистка выполняется только для `workspace: none` (приватный `run/`) и `workspace: worktree` (агентский `work/`).
- Для `workspace: direct` чистка транскриптов ЗАПРЕЩЕНА: слот `$CLAUDE_CONFIG_DIR/projects/<slug(project)>` общий с человеческими интерактивными сессиями в той же папке - удалять оттуда нельзя ничего.

## 6. Снапшот-манифест (workspace: direct)

Замена git-диффа для приемки:

- Перед прогоном: манифест файлов проекта - относительный путь, размер, mtime, sha256 (файлы > 20 МиБ - без sha256, только размер/mtime). Исключения: `.git/`, плюс глоб-список из `spec.snapshot_exclude` (опционально).
- После прогона: дифф `{added: [], modified: [], deleted: []}` durable в `agents/<name>/changes/<key>.json` (key - ключ конверта).
- В хвост `meta.result` - краткая сводка ("изменено N, добавлено M: <первые пути>").
- Fail-open с пометкой: > 20000 файлов или ошибка манифеста -> прогон НЕ блокируется, в changes-файл пишется `{"skipped": "<причина>"}`.

**Границы обхода (аудит V2.1, major 3/4):**

- Обходятся **только регулярные файлы**, определяемые через `os.lstat` (без разыменования): симлинки, FIFO, сокеты, устройства в манифест не входят и НЕ открываются (FIFO блокирует `open` навсегда - зависание вне `run_timeout_s`).
- `snapshot_exclude` применяется и к каталогам (prune в `os.walk` через `dirs[:]`), а не только к файлам - иначе исключенное дерево все равно обходится целиком.
- Жесткие лимиты, любой из которых дает `skipped` (манифест = None): > `SNAPSHOT_MAX_FILES` файлов, > `SNAPSHOT_MAX_BYTES` суммарно захешировано (дефолт 2 ГиБ), > `SNAPSHOT_DEADLINE_S` секунд на построение (дефолт 120). Все три - env-override.
- **Честный fail-open:** ошибка обхода (`os.walk(onerror=...)`) -> манифест None -> `{"skipped": ...}`. Ошибка `lstat`/чтения отдельного файла -> запись остается в манифесте с меткой `{"error": true}` (не исчезает), иначе временно недоступный файл ложно попадет в `added`/`deleted` следующего диффа.

## 7. Промпт-рамка (гейт по workspace, r1 #14 остается в силе)

- `worktree`: "cwd - worktree задачи (ветка B) проекта P; коммить в свою ветку; main не трогать, push не делать".
- `direct`: "cwd - живая папка проекта P без изоляции; новые файлы создавать можно; существующие правь только когда это прямо требуется задачей; деструктивных операций избегать".
- `none`: рамка без workspace-блока (байт-в-байт как сейчас).

## 8. Preflight reconciler

Снять допущение "event = без worktree/mount-проверок": для event с `workspace: worktree` - те же mount/`git rev-parse` проверки перед стартом, что у mission; для `direct` - существование и доступность каталога `project`. Провал preflight - как у mission (старт не идет, лог; без новых attention-механизмов).

## 9. Регресс-инварианты

- Спека без `workspace`/`permissions` -> поведение байт-в-байт (argv, cwd, ретеншн).
- mission-путь не меняется (его settings-генерация при create остается как есть).
- Blacklist ревьюера не меняется.
- V2.0 (drain/ready-гейт) не затрагивается.

## 10. Тесты

Юнит (стиль tests/, mock-claude через CLAUDE_BIN; mock умеет печатать `$PWD` и создавать файл в cwd по режиму):

- U1: спека с permissions -> agent-settings.json создан с allow/deny из спеки; argv содержит `--settings/--setting-sources user/--permission-mode`, НЕ содержит `--disallowedTools`.
- U2: спека без permissions -> argv со старым blacklist байт-в-байт.
- U3: argv ревьюера не изменился (голден-сравнение списка).
- U4: cwd по workspace: none -> `run/`; direct -> папка проекта (mock печатает PWD, тест сверяет).
- U5: create event+worktree -> `work/` существует, ветка `task/<name>-*` есть, HEAD совпадает с базой; существующая ветка -> create падает, каталог агента НЕ создан (staging откатился).
- U6: валидация create: worktree на не-git -> fail; direct на несуществующую папку -> fail; workspace=мусор -> fail.
- U7: direct-прогон, mock создает файл -> `changes/<key>.json` содержит его в added; второй прогон без изменений -> пустой дифф.
- U8: после прогона workspace!=none в тестовом `$CLAUDE_CONFIG_DIR/.claude.json` появился `hasTrustDialogAccepted` для realpath(cwd).
- U9: transcripts_cleanup для direct не вызывается/не чистит; для none чистит slug фактического cwd.
- U10: create event+permissions+`autonomy: act` проходит; event без permissions с act - fail (как сейчас).

Кейсы по аудиту V2.1 (добавляются в тот же файл):

- U11: `permission_mode: bypassPermissions` в спеке -> create exit 2; при подмене спеки после create runner форсит `default` (argv-дамп это показывает).
- U12: `permissions: []` и `permissions: {allow: 1}` -> create exit 2; при подмене после create runner не падает и уходит на старый blacklist-argv.
- U13: FIFO и симлинк в direct-проекте -> манифест строится без зависания, они в него не входят; `snapshot_exclude` с каталогом -> дерево не обходится (проверяется по времени/по отсутствию его файлов в diff).
- U14: недоступный для чтения файл присутствует в манифесте с меткой ошибки и НЕ появляется как added/deleted в следующем диффе.
- U15: параллельные preseed-вызовы (N процессов) -> `.claude.json` валиден, все ключи на месте; битый `.claude.json` -> переписан минимальным валидным с trust.
- U16: U9 считает ожидаемый slug от `realpath(cwd)`.

Интеграционный (fault-suite, после юнитов, отдельным шагом):

- S21a: drain-агент workspace=worktree на тестовом репо: событие -> прогон в worktree (mock коммитит) -> ветка получила коммит, main не тронут, юнит вышел штатно.
- S21b: drain-агент workspace=direct на папке: mock создает файл -> файл на месте, changes-дифф зафиксирован.

## 11. Критерии приемки этапа (из плана v2)

- sandbox-задача правит файл в worktree, коммитит в свою ветку, main не тронут (S21a).
- direct-задача на не-git папке создает файл, дифф-список зафиксирован (S21b, U7).
- deny из пояса реально блокируется (проверяется на живом claude при обкатке на sandbox - мок это не докажет; в юнитах фиксируется только передача флагов).
- Спека без permissions/workspace - поведение байт-в-байт старое (U2, U4-none, регрессы V2.0).
