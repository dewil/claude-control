# Доменные спеки claude-control

Заведены 19.09.2026, когда проект принял SDD-конвейер как планку (`.claude/rules/sdd-pipeline.md`). До этого намерение жило в 22 контрактах этапов `docs/design-*.md`, в памяти проекта и в решениях dwl; спеки собирают его в одно место и в настоящем времени.

**Что здесь лежит.** По файлу на домен: границы, инварианты с доводом "почему", внешние контракты, решения с датами, известные дыры, трассируемость. Спека пишется **от замысла**, а не с кода: решения dwl и контракты этапов весомее того, как код ведет себя сейчас. Спека, снятая с кода, узаконивает баги.

**Чего здесь нет.** Истории этапов (она в `docs/design-*.md` и в памяти проекта), инструкций по эксплуатации (`docs/runbook-*.md`), человеческого описания системы (`README.md` в корне, `docs/architecture.md`).

## Идентификаторы и трассировка

Схема одна на проект: **`INV-<ДОМЕН>-NN`**, где `<ДОМЕН>` - код из таблицы выше, `NN` - сквозной номер внутри домена, который **не переиспользуется**: снятый инвариант оставляет дыру в нумерации, а не отдает номер следующему.

Тест-раннер здесь - bash-скрипты со счетчиками `ok`/`fail`, поэтому тег ставится **строкой в тесте**: идентификатор пишется в комментарии над проверкой и в тексте `fail`, чтобы он был виден и в исходнике, и в выводе упавшего прогона.

```bash
# INV-SESS-07: headless-прогон не попадает в список сессий
if ! grep -q '^eeeeeeee' "$OUT"; then ok; else fail "INV-SESS-07: headless-прогон в списке"; fi
```

**Rot-guard** - грепом, без отдельной инфраструктуры:

```bash
grep -rl 'INV-SESS-07' tests/    # пусто = инвариант не покрыт, что бы ни было в таблице
```

Инвариант без тестов - не дефект спеки, а честная строка "нет" в разделе трассируемости. Поле "чем проверено" не бывает пустым.

## Порядок работы

Изменение, меняющее наблюдаемое поведение, идет по конвейеру (`sdd-pipeline.md`): спека фичи в `docs/dev/<дата>-spec-<фича>.md`, тесты вслепую, реализация, сверка второй моделью, документы в том же PR. Правка, доказуемо не меняющая поведения, идет обычным PR.

Расхождения спеки с кодом, найденные аудитом, живут в `docs/dev/backlog/<дата>-<домен>-findings.md` и строкой в разделе "Известные дыры" соответствующей спеки. `docs/dev/` не уходит в публичный репозиторий (`.gitignore`), `docs/specs/` уходит.
