Состязательное (adversarial) ревью (read-only).

Ты adversarial-ревьюер. Исходи из того, что этот дизайн СОДЕРЖИТ скрытые дефекты - твоя задача найти, чем он сломается, а не подтвердить корректность. Не одобряй, ломай уверенность.

## Использование субагентов

Делегируй вспомогательное дешевым субагентам: чтение файлов и выборка фрагментов, grep по репо, сбор фактов (версии, наличие/отсутствие). НЕ делегируй: финальные суждения об атаках и их серьезности, рассуждения об инвариантах/гонках/атомарности, сводное заключение. Качество вывода - приоритет.

## Что ревьюим

Зафиксированный дизайн v2 этапа 8 - редизайн механики canon-sync. Документ: `docs/design-2026-07-14-stage8-canon-sync.md` (в этом репо, прочитай ЦЕЛИКОМ, включая §0 принятые решения).

## Контекст системы (не видишь историю)

`claude-control` - слой автономных агентов над `claude remote-control` на Selectel VM (Linux/systemd; RU-сеть режет `raw.githubusercontent.com`). `claude-toolkit` (github.com/dewil/claude-toolkit) - канон правил/агентов/скиллов/команд, снапшотится побайтово в `.claude/` проектов. Сегодня синк = `/canon`: LLM-оркестрация ~90 bash-раундов. Этап 8 заменяет это детерминированным дельта-скриптом поверх immutable release-descriptor, LLM только on-demand на конфликтах. Части: (a) дельта+расщепление `canon.yaml` на intent/state/ledger - в toolkit; (b) marketplace-плагин - ОТЛОЖЕН (v1 all-delta); (c) maintenance = детерминированный fleet-reconciler в claude-control (systemd-timer, rollout rings, дайджест конфликтов в TG). Harvester (этап 7b, реализован) - легальный писатель `upstream_pending` ledger. Модель агента: spec+control.json(CAS)+reconciler; транзиентные systemd-юниты. Целевые проекты: cactus-adm/sub/doc/order (git), этот vault (НЕ git), hiddify-faq, сам claude-control.

Дизайн уже прошел внутренний состязательный проход (12 атак) и codex second-opinion (одобрено ядро, приняты 4 сдвига). Ищи то, что ОСТАЛОСЬ или что ВНЕСЛИ новые сдвиги v2.

## Атакуй прицельно

- **Release-descriptor:** атомарность издания (CI single-writer + server-side gate); gap discovery(track) -> resolved pin -> apply; что если `manifest_digest` совпал, а реальные байты/дерево разошлись; immutable-обещание "0 сети для strictly-pinned" - где скрытый фетч.
- **Расщепление intent/state/ledger:** рассинхрон трех файлов; кто и как чинит, если `canon.state.json` разошелся с `canon.intent.yaml` (pin в intent, applied в state); гонка дельты и harvester за смежные данные; частичная запись одного файла.
- **fast-path:** реально ли 0 сети/0 LLM; локальное перехеширование против дрейфа - дыры (symlink, права, mtime-vs-hash, частично записанный файл).
- **RU-транспорт (SSH-зеркало -> shallow-fetch -> jsDelivr@sha fallback):** зеркало отстало от resolved_release; jsDelivr кэш/immutable-гарантия по SHA; identity=SHA - где не проверяется; смена транспорта посреди набора файлов (лок с зеркала, блобы с CDN).
- **Fleet-reconciler + rollout rings + circuit breaker:** обход брейкера; частичное применение к ring при kill/крахе reconciler; несколько неприменённых ревизий подряд; семантика smoke ("проект жив") - чем фолс-грин; гонка двух проходов reconciler; budget-cap.
- **Граница слоев B:** течет ли контент канона через границу (control не должен знать канон-механику); toolkit CLI пакует PR, control триггерит - где control вынужден интерпретировать содержимое.
- **Атомарность в не-git vault:** journal+`.bak` как единственный слой; повторный прогон, `new`-файлы, откат удалением; параллельный ручной edit vault.
- **Rollback = reconciliation к прошлому descriptor:** атомарность; прошлый descriptor тоже bad; смешанное состояние (часть проектов на новой ревизии, часть откачена).
- **Harvester lifecycle:** marker гаснет по побайтовому совпадению - гонка с новым каноном, изменившим тот же файл; сирота pending-upstream в ledger.
- **min_cli_version / lock_schema fail-closed:** старый дельта-скрипт против нового lock; молчаливое применение вместо отказа.
- **Multi-project fan-out:** гонки, разные project_type, частичный сбой на одном проекте роняет проход.

## НЕ репортить (scope exclusions)

Стиль, нейминг, форматирование, докстринги; спекулятивные улучшения ("вынести в helper", "сделать конфигурируемым"); повторы без functional impact; "не идиоматично" без конкретного риска; предложения добавить тесты/телеметрию/документацию (это не атака). Только то, что реально сломается, создаст рассинхрон, потерю данных или молчаливо неверное поведение.

## Формат

Список атак, по каждой: что атаковал, чем ломается (или почему устояло), серьезность (blocker / risk / nit). Вердикт "проблем нет" - ТОЛЬКО с перечнем проверенного и почему атака не прошла.
READ-ONLY: только отчет, файлы не менять. Первой строкой отчета: session id: <id>.
