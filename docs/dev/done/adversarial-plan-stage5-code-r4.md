# Ревью r4: закрытие 2 остатков r3 (read-only, тугая рамка)

Первой строкой: `session id: <id>`.

Та же сессия. r3 дал НЕТ из-за двух: (1) окно mv..trap-clear могло снести
опубликованного агента; (5) фиксированный `.part` делили параллельные retry. Я
применил ровно твои предписания. Проверь ТОЛЬКО их + регрессию. НЕ переоткрывай
принятые residual'ы (design §4.2).

## Закрытия

1. **trap-guard (r3-1)** `bin/claude-rc-agent`: EXIT-trap теперь `if [ ! -e
   '$AGENTS_DIR/$name' ]; then <rm tmp; prune; [_BR_OWNED=1] branch -D>; fi`.
   Успешный `mv` создаёт финальный реестр -> trap НИЧЕГО не трогает (структурная
   граница ownership, как ты предложил). До mv финала нет -> чистка работает.
   Проверь: (a) catchable-сигнал в окне mv..trap-clear больше не сносит ветку/
   worktree (final существует -> guard пуст); (b) чистка на провале ДО mv цела;
   (c) recreate с чужой веткой не удаляет её (_BR_OWNED=0 + final отсутствует, но
   ветка чужая -> branch -D под _BR_OWNED=0 не выполняется).

2. **unique .part (r3-5)** `bin/claude-rc-takeover`: `n=$$`; scp во
   `spec.yaml.$n.part`/`mission.md.$n.part` -> `mv -f` в final. Два параллельных
   вызова (разные pid) не делят inode. Проверь: нет пути, где reader final видит
   растущий файл; bundle "новый spec+старый mission" при разном контенте одного
   commit - принят как residual (design §4.2), не блокер.
