   теперь делает `branch -D 'agent/<name>'` под отложенным `\$_BR_OWNED` (глобал,

   show-ref-предчека (agent:326), т.е. любой краш-путь ДО `mv` (agent:390) - вкл.
   регион stale-scratch/settings ПОСЛЕ post-check - теперь чистит нашу ветку.
   `trap - EXIT` (agent:391) сразу после mv -> окна "удалить ветку опубликованного
   агента" нет. Явные `_wt_cleanup` убраны (trap покрывает).
   **Остаточные (design §4.2, приняты как pre-existing, НЕ 5-специфичны):**
   SIGKILL (trap не ловится) и гонка двух одновременных `create` ОДНОГО имени
   (окно show-ref/ref) - ручное восстановление по сообщению. Полный lock/CAS -
   будущее ужесточение create.
   Проверь: (a) recreate с чужой живой веткой всё ещё fail 4 БЕЗ её удаления
   (_BR_OWNED=0 в тот момент); (b) провал в регионе ПОСЛЕ post-check до mv чистит
   нашу ветку; (c) trap не удаляет ветку после успешного mv.
