## Три закрытия (проверь по коду)

1. **reject fail-closed (r6 п.5)** - `bin/claude-agent-harvest`:
   - `_remove_brief`: fsync каталога после unlink теперь `die(7)` при OSError
     (было `pass`) - durable cleanup гарантирован до смены статуса.
   - `cmd_reject`: ОТСУТСТВУЮЩИЙ `canon.yaml` -> `die(3)` ДО чистки (было:
     пропуск _canon_rmw + смена статуса). Теперь canon обязателен, `_canon_rmw`
     вызывается всегда, статус меняется только после успешной чистки.
   Проверь: нет пути, где статус -> upstream-rejected, а бриф/canon-запись
   остались; re-run после починки canon доводит (self-heal); идемпотентность
   `already`-ветки цела.

2. **incarnation present-vs-absent (r6 п.7)**:
   - `agent_incarnation`: `if isinstance(ctrl,dict) and "incarnation" in ctrl`:
     валидный hex32 -> он; иначе -> `None` (агент ПРОПУСКАЕТСЯ, НЕ legacy).
     Fallback на `agent_created` - ТОЛЬКО когда ключа НЕТ (legacy-агент 1-7).
   - `bin/claude-agent-io` `validate_control`: `if "incarnation" in doc` ->
     обязан hex32; явный `null` теперь невалиден (было `is not None`).
   Проверь: битый/null incarnation больше НЕ падает в legacy (старые события не
   переэмитятся); legacy-агент БЕЗ ключа всё ещё различается по agent_created;
   control-cas legacy-агента (без ключа) не сломан.

3. **Немаскированные ledger-поля (r6 новый)** - `cmd_collect`:
   - имя каталога агента валидируется `NAME_RE` (невалидное -> `continue`,
     не попадает в ledger/prompt/digest/brief как "agent").

   Проверь: каталог вида `token=SECRET` не даёт записи и не утекает; валидные
