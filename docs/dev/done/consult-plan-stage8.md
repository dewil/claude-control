## Использование субагентов

По возможности делегируй вспомогательную работу собственным субагентам на более дешевых моделях:
- поиск файлов/символов, grep по репо;
- чтение больших файлов и выборка релевантных фрагментов;
- сбор фактов (версии, конфиги, наличие/отсутствие чего-либо).

Что НЕ делегировать дешевым моделям:
- финальные суждения о подходе (согласен / не согласен + альтернативы);
- рассуждения об архитектуре, инвариантах, кросс-слойных границах;
- сводное заключение в конце отчета.

Главный критерий - качество итогового вывода. Если задача требует основной модели - используй основную модель.

## Контекст системы (не видишь историю - вот суть)

`claude-control` - слой автономных агентов над `claude remote-control` на Selectel VM (Linux/systemd; RU-сеть режет `raw.githubusercontent.com`). Отдельно есть `claude-toolkit` - git-репо (github.com/dewil/claude-toolkit): канон правил/агентов/скиллов/команд, снапшотится побайтово в `.claude/` проектов.

Синхронизация СЕГОДНЯ - слэш-команда `/canon`: тонкий загрузчик фетчит ~50KB LLM-промт и исполняет его как LLM-оркестрацию ~90 bash-раундов (curl+shasum по каждому из ~45 файлов, 3-стороннее сравнение base/local/upstream, autodiscovery новых канон-файлов, пофайловый диалог). No-op синк (канон не менялся) жжет десятки тысяч токенов, потому что оркестратор - LLM. `canon.yaml` в проекте: `project_type[]`, `canon.{repo,raw_base,branch}`, `files[~45]`, `file_hashes{путь->sha256}`, `local_only[]`, `skip_sync[]`, `upstream_pending[]`. Файлы копируются точными байтами (без symlink, без LLM-мерджа); `rules|agents|skills|commands/<x>` -> `.claude/<x>`, `scripts/<x>` -> корень проекта. Версионирования (тег/ревизия/changelog), pin, rollback, precedence, marketplace-плагина - сегодня НЕТ.

Этап 8 кросс-слойный: (a) ревизии+дельта-скрипт и (b) marketplace-плагин с precedence/pin/rollback - изменения в `claude-toolkit`; (c) maintenance-агент `canon-maintainer` - в `claude-control`. Уже реализован harvester (этап 7b) - поставляет одобренные правила в канон через `toolkit-log/upstream-pending`, естественный вход для (c). Модель агента claude-control: spec.yaml (неизменяем) + control.json (CAS) + reconciler-надзор; тип mission|event; транзиентные systemd-юниты; autonomy suggest|act|release.
