## Использование субагентов

По возможности делегируй вспомогательную работу собственным субагентам на более дешевых моделях:
- поиск файлов/символов, grep по репо;
- чтение больших файлов и выборка релевантных фрагментов;
- сбор фактов (версии, конфиги, наличие/отсутствие чего-либо);
- проверка тривиальных условий ("есть ли тест на X", "используется ли функция Y").

Что НЕ делегировать дешевым моделям:
- финальные вердикты по статусам пунктов;
- сводное заключение в конце отчета.

## Исходная постановка этапа 4 (объем)

1. `claude-agent-run`: inbox at-least-once.
2. Дедуп (повтор не дублирует эффект).
3. Dead-letter.
4. Ретеншн (inbox, dead-letter; по контракту §11.3 - done 14 дней, deadletter до разбора, pending/inflight/курсор не трогать).
5. Бюджет-предохранитель: капы прогонов/сутки И недельного расхода - СТОП с алертом, не только показ.
6. Первый источник событий.
7. Недоверенный вход - минимальные руки (модель доверия п.2 плана: без Bash, без чувствительных MCP, suggest).

Критерии готовности этапа (из плана):
- kill -9 не теряет событие;
- повтор не дублирует эффект;
- ядовитое событие уходит в dead-letter, очередь живет;
- при исчерпании капа раннер останавливается с алертом.

Контрактные требования основного дизайна, входящие в постановку:
- §11 event-контракт: конверт (единый файл meta+payload, переход = rename), intake FSM (RUNNING/DEGRADED/WEDGED, строго по одному элементу, contiguous-курсор коммитится ПОСЛЕ элемента, pending пишется ДО курсора), executor FSM (singleton flock + cgroup, PICK старейшего с next_attempt_at<=now и не quarantined, CLAIM=rename, инфра-гейт наблюдаемых FAIL, ретраи 1/5/15 мин, attempts>=3 -> deadletter + алерт, recovery inflight с мертвым runner: key в dedup -> done, иначе probe-гейт + recoveries++, recoveries>5 -> quarantine + attention crash_loop c subject, FIFO до первого retry, один прогон на агента, DLQ разбирает человек).
- §11.3 дедуп-леджер: flock, tail-truncate до полного \n при открытии на запись, append+fsync ДО rename inflight->done, set-семантика читателя, restore только командой inbox-restore.
- §10.2: срабатывание капа -> hold budget_exhausted + алерт, прогоны и захваты стоп, intake ПРОДОЛЖАЕТ.
- §10.3: inbox_max_events/bytes, 100% -> wedged + attention inbox_wedged, lease при этом ЗАХВАТЫВАЕТСЯ (drain - лекарство), потеря наблюдаема (алерт при возрасте старейшего непотребленного > 50% replay-окна).
- §16.1 (event-строки): inbox_wedged/infra_down/crash_loop/dlq_overflow разрешают захват; самоснятие средовых (wedged при <60%, infra_down при здоровом probe).
- §4.2: глаголы dlq [--requeue|--drop], inbox-restore (re-init курсора и леджера от живого источника), attach для event = отказ (4).
- §6.4: event-рантайм = транзиентный agent-<name>.service, Type=exec, claude-agent-run как MainPID, headless-дети в том же cgroup.

Конкретизации, принятые дизайн-дельтой docs/design-2026-07-12-stage4-event-spool.md (7 adversarial-раундов, вердикт ПРИНЯТ) - считать частью постановки: первый источник = spool-каталог с producer-протоколом; продюсер #1 = /task в tgbot; intake хостится в проходе reconciler'а; бюджет v1 = капы ЧИСЛОМ прогонов + опциональный best-effort недельный USD-кап (явная ревизия §10.2 - недельный расход в деньгах отложен до парсера транскриптов); прогон в пустом приватном cwd.
