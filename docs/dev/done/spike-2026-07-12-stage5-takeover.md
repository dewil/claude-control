# Спайк этапа 5: takeover (кейсы B и C)

Цель (план, этап 5): проверить механику перехвата сессии, критерий - "прерванный handoff без двойного владения; go/no-go".

- **Кейс B**: локальная сессия на Mac -> tmux под claude-control (адопция на той же машине, вне агентного слоя - reconciler Linux-only).
- **Кейс C**: сессия на Mac -> VM (кросс-машинный перенос транскрипта, продолжение под relay на VM).

## Эксперименты

- **C1 (crux)**: транскрипт, созданный на Mac, переносится scp на VM в namespace VM-cwd; `claude --resume <sid>` на VM. Проверяем: память сессии, сохранение session_id (не форк), толерантность к Mac-путям в истории, версии claude.
- **C2**: то же + `--remote-control` - видимость с телефона.
- **B1**: на Mac - адопция завершенной сессии в tmux с `--remote-control` (механика этапа 2, но на Darwin: нет /proc - триада живости origin требует ps/kill -0 вместо /proc/<pid>/stat).
- **Двойное владение (аналитика)**: кросс-машинно VM не может проверить живость Mac-процесса -> протокол должен быть push-based: Mac-сторона сама доказывает смерть origin (release-маркер после exit) ДО импорта на VM. Зафиксировать требования для имплементации.

## Требования к протоколу takeover (для имплементации, не спайк)

Двойное владение - главный риск: VM **не может** проверить живость Mac-процесса через `/proc` (другая машина, другая ОС). Значит commit-триаду этапа 2 (origin_pid + starttime из /proc) кросс-машинно применить нельзя. Протокол обязан быть **push-based**:

1. **Origin (Mac) доказывает свою смерть сам**: после `exit` пишет durable release-маркер (session_id + hostname + timestamp + "released") в переносимый рядом с транскриптом файл. Импорт на VM разрешён только при наличии маркера.
2. **Fencing по hostname**: приёмник (VM) сверяет, что маркер выпущен ожидаемым origin-хостом; чужой/отсутствующий маркер -> отказ, не импорт.
3. **Транспорт** сам не гарантирует смерть: scp копирует, но не убивает донор. Поэтому release-маркер - единственное свидетельство; без него takeover запрещён (fail-closed), как MOVE-адопция запрещена без commit-триады в §9.
4. **Идемпотентность**: повторный импорт того же sid при уже адоптированной сессии на VM - no-op (дедуп по sid в реестре приёмника).

Кейс C для агентного слоя = mission-агент с `--handoff-*`, где origin_cwd/pid заменяются на release-маркер Mac-стороны. Это доработка `create --handoff` + `handle_handoff` в reconciler, отдельным этапом.
