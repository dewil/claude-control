## Как сведены 5 TRUE-блокеров раунда 3

`docs/design-2026-07-13-stage7b-harvester.md` (v4, читай Threat-model, Д2,
Д4, Д8, Д9, Д11, Остаточные риски).

1. **Human gate исполним агентом** -> threat-model ВЫРОВНЕН под системную
   модель claude-control (план, принцип 1): защита от ОШИБОК/шума, НЕ от
   злонамеренного same-UID агента. Агент и так всевластен (может сам вызвать
   approve, писать в canon/role) - это СИСТЕМНАЯ дыра, закрываемая общей
   изоляцией (отложена для всего claude-control, не 7b-специфично). 7b НЕ
   претендует защитить human gate от атаки; human gate = фильтр КАЧЕСТВА
   сигнала. Это та резолюция, что ты сам предложил ("признать процесс агента
   недоверенным, но не злонамеренным").
2. **Approve не привязан к контенту** -> `candidate_id = sha256([sorted
   ids, essence, why, how])` включает КОНТЕНТ; emitted IMMUTABLE; approve
   fail-closed сверяет id с записью. Другая essence = другой id -> approve
   экспортирует ровно просмотренное.
3. **No-follow raceable** -> commonpath (не строк-префикс) + realpath-assert
   (в корне И не в agents/) + O_NOFOLLOW. TOCTOU-подмена ancestor - атака
   same-UID, вне scope v1 (threat-model); race-free dirfd - в фазу изоляции.
4. **Экспорт в LLM до human gate** -> LLM-провайдер объявлен ДОВЕРЕННЫМ
   sink (как любой `claude -p` в claude-control: приёмщик шлёт дифф,
   event-агент - payload). Отправка данных провайдеру - принятый системный
   факт, не новый вектор 7b.
5. **Durable RMW canon.yaml** -> parse+validate старого -> durable_write
   (tmp O_EXCL, write-all, fsync, rename, fsync каталога) -> re-validate;
   повреждённый старый -> отказ. Каждый из 3 файлов approve independently
   durable + идемпотентен (re-run сходится). Общий ACID признан
   over-engineering для human-gated шага.

## Задача раунда 4 (тугая рамка - НЕ ищи атаки вне модели)

threat-model v4 ЯВНО: "ошибки, не злоумышленник", выровнено под системный
принцип 1 (изоляция отложена для ВСЕЙ системы). НЕ репортить как блокер
атаки злонамеренного same-UID агента (сам approve, прямая запись в canon/
role, эксфильтрация через LLM, TOCTOU-подмена) - они ЯВНО вне scope v1
системно, не 7b-специфично.

Ответь строго:

1. По каждому из 5 блокеров р3: СВЕДЁН / НЕ сведён (в рамках выровненной
   модели). Если не сведён - почему СВЕДЕНИЕ неверно (а не "агент всё равно
   может атаковать" - это вне scope).
2. Остались ли дефекты, ломающие дизайн В МОДЕЛИ "ошибки, не злоумышленник"
   (крэш/повреждение данных/логическая некорректность/потеря сигнала БЕЗ
   активной атаки)? Если да - перечисли как БЛОКЕР-в-модели.
3. Выравнивание threat-model под системный принцип 1 - ЛЕГИТИМНО (7b не
   обязан быть безопаснее системы, где живёт), или это уклонение (есть
   причина, почему 7b ТРЕБУЕТ более высокой планки, чем остальной
   claude-control)?
