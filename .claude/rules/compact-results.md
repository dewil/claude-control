# Компактный вывод в чат по умолчанию

Беречь выходные токены основного контекста: выходной токен дороже входного и под прямым контролем Claude. Правило - про то, что уходит в чат: и вывод тулов, и собственная генерация Claude. Про вход и делегирование субагентам - `subagents-usage.md`.

## Результаты проверок

Рутинные проверки отдавать компактно; развернутый вывод - только когда есть что чинить.

- **Прошло** - одна строка с итогом: `тесты: 12/12 ok`, `lint ok`, `build ok`, `деплой ok`, `проверка X: 200 ✓`. Без эха всего лога.
- **Упало** - показать только релевантный кусок: имя упавшей проверки плюс assert/ошибку/нужную строку вывода. Не весь verbose-лог.

Где применять: тесты (сводка `N/M ok`, при падении - упавшие кейсы), линт/типчек/сборка (статус строкой, при ошибке - конкретные сообщения), сетевые проверки (итог плюс код ответа, не полный `-v`), деплой (финальный статус, не построчно), удаленные команды (результат, не эхо самой команды).

## Собственная генерация

- **Без преамбул и постамбул.** Не пересказывать вопрос, не открывать ответ ("сейчас гляну..."), не закрывать резюме того, что и так видно в диффе.
- **Не эхо-ить вход.** Прочитал файл - не вставлять содержимое обратно. Ссылка по `path:line`, не цитата блока.
- **Не показывать полные файлы и диффы после правки.** Описать изменение словами плюс ссылка на строки. Edit и так подтверждает успех. Полный файл или diff - только если пользователь попросил.
- **Молча отбрасывать мелкие технические варианты.** Не проговаривать отвергнутые детали реализации одного уровня ("можно было бы так, но..."). Развилки, где нужен выбор пользователя или есть неочевидный trade-off, - наоборот, вынести на поверхность (`karpathy-guidelines.md`, п.1).
- **Планы тезисно.** Короткий чеклист, а не абзац обоснований на каждый шаг.
- **Структура плотнее прозы.** Список, таблица, schema где уместно.

## Чего не делать

- Не глушить падающие проверки ради краткости. Краткость - для зеленых прогонов; красные показываем по делу (это не противоречит правилам про покрытие тестами).
- Не вставлять полные дампы (логи, JSON, длинный stdout) в основной чат. Такие выводы - через субагента с возвратом итога в N строк (см. экономию токенов в `subagents-usage.md`).
- Не жертвовать ясностью ради краткости. Убирать паддинг, а не содержание: нужное объяснение, предупреждение о риске, ответ на заданный вопрос остаются.
