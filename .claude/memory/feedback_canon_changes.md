---
name: Подготовка изменений для канона
description: Как вынести правило/патч в канон claude-toolkit - бриф в toolkit-log, без git
type: feedback
---

Когда просят подготовить патч/изменение для канона claude-toolkit или "вынести правило наверх" - не делай ради этого git-операций: не коммить, не пушь, не создавай ветки, не пытайся клонировать или править claude-toolkit. Этот проект подключен к канону по HTTP и доступа к его репозиторию не имеет.

Вместо этого создай самодостаточный бриф `toolkit-log/upstream-pending/<slug>.md` (целевой путь в каноне, предлагаемое содержимое точным текстом, rationale) и допиши запись в `.claude/canon.yaml -> upstream_pending`.

**Why:** проект не знает, где на машине лежит клон claude-toolkit; единственный безопасный канал наверх - самодостаточный артефакт, который пользователь сам отнесет в клон. Git-операции отсюда либо бессмысленны, либо опасны (правят не тот репозиторий).

**How to apply:** дальше пользователь открывает свой клон claude-toolkit, скармливает бриф местному Claude, ревьюит, коммитит, пушит. На следующем sync проект увидит, что файл доехал в канон, и перенесет бриф в `toolkit-log/upstream-applied/`. Это то же, что делает sync-from-canon при обнаружении ценного локального правила, но доступно вне синка.
